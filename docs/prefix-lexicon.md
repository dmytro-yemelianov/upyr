# EN/UK physical-key prefix lexicon

The early correction path needs evidence about unfinished words. A whole-word
language model or imported rule can flag a suspicious substring while the
source is still a valid beginning of a name or word. The generated prefix
lexicon records which language can continue each physical key sequence.

For example, `dbgh` has Ukrainian continuations (`випр…`) and no English
continuation in these sources. Combined with the imported `bgh` rule and EN/UK
prefix scores, it corrects to `випр` after four letters. Typing the remaining
keys completes `виправлення`. `rehn`, in contrast, has both English and Ukrainian
continuations and is preserved. Lexical absence alone never initiates a change.

## Sources and reproduction

`tools/generate_prefix_model.py` builds from checksum-pinned inputs:

- Leipzig `eng_news_2023_1M` and `ukr_news_2023_1M`, the same news snapshots used
  for the existing signed n-gram model.
- FreeBSD Web2 at revision `4a65e12dfbaba7193e37fcd2e14fbc20776a78b9`, supplementing
  English with dictionary words, including uncommon forms.

The generator case-folds, normalizes apostrophes, splits hyphens, accepts only
language-alphabet tokens of 2–48 characters, and retains all positive-frequency
word forms. Ukrainian forms are transformed to their physical EN key positions.
The resulting vocabulary has 439,289 English and 306,516 Ukrainian forms.
The adjacent `assets/models/prefixes.json` manifest records URLs, source hashes,
mappings, normalization, counts and the output hash. Attribution and the Web2
source notices are in `THIRD_PARTY_NOTICES.md` and `prefixes-web2-NOTICE.txt`.

```sh
python3 tools/generate_prefix_model.py
python3 tools/generate_prefix_model.py --check
python3 -m unittest tools.test_generate_prefix_model
```

Downloads are cached under `.cache/upyr-corpora`. Generation never reads recall
fixtures or the Wikipedia holdout. The Web2-based recall fixture naturally
shares dictionary coverage; the separately sourced Wikipedia sample is the
external evaluation. The existing whole-word n-gram artifact and boundary
policy are unchanged.

## Representation and decision

The initial 1,932,187-node combined trie is minimized by merging states with
identical language masks and outgoing transitions. The resulting acyclic
automaton has 311,394 states and 765,685 edges, occupying 4,308,336 bytes.
It is embedded read-only and queried without allocation or runtime compilation.

The `UPYRLP1\0` header contains little-endian u32 node count, edge count and root
ID (20 bytes total). Each 4-byte node packs a 24-bit first-edge index, 6-bit
edge count and 2-bit continuation language mask. Each 4-byte edge packs a
24-bit child ID and an 8-bit physical key. Edge keys are sorted; child IDs point
backward. The generator checks field limits; Rust tests validate every stored
edge, mask, offset and the acyclic ordering.

Before an imported early correction can apply:

1. A Punto trigger or persistent substring/beginning source rule must match.
2. The physical prefix must have a target-language continuation and no
   source-language continuation in the lexicon.
3. Conservative EN/UK open-prefix evidence must favor the target.
4. Existing length, installed-layout mapping, identifier, exception, keep,
   focus and edit-cancellation guards must permit the change.

An explicit user prefix-correction rule retains its existing behavior. Exact
imported source rules do not independently justify correction before a boundary.
The lexicon is finite: membership is evidence, not proof about every possible
word, name or language use.

## Initial incremental traversal and measurements

The first incremental change added the lexical cursor to `PartialWordState`.
The cursor stores the normalized physical prefix and the state reached after
each of up to 64 bytes in fixed arrays (336 bytes on ARM64). After validating the shared input bytes, an append
walks only the new suffix; Backspace restores an earlier state without walking
from the root. A replacement walks from the longest unchanged prefix. Dead
branches remain recoverable by deleting the offending characters. Clearing
context or completing a word resets the cache. No heap allocation is needed
for the cursor or its lookups.

At this stage only lexical transitions were cached. The current layout, mapping, policy,
case-sensitive Punto rules, exceptions and other guards are reevaluated on every
call. The stateless `evaluate_partial` API remains available; the desktop uses
`PartialWordState::evaluate`. Prefix byte validation also makes reuse safe after
skipped samples or cancellation. This optimization avoids repeated automaton
walks; it does not eliminate the bounded prefix-byte comparison.

## Streaming engine optimization

The next five stages retain the existing rules, dictionaries, models and
decisions while reducing repeated work outside the lexical index:

1. The desktop adapter prepares the policy once per change to sensitivity,
   minimum length, exception list or rule text. Exact value comparisons also
   catch learned rules and in-place configuration edits. Installed-layout pairs
   use a shared immutable snapshot with the same lifetime as the platform cache.
2. The live partial-word path borrows the tracker's word and reuses conversion
   buffers. It no longer creates an owned word/context snapshot or full-word
   candidates on every key. Replacement strings are allocated only for an
   actual correction. Normalized user exceptions are reused until their list changes.
3. Integer prefix sums cache n-gram evidence. Append scores only grams ending
   at new characters; Backspace restores a saved sum; branch edits recompute
   from the first changed character. The resulting floating-point scores match
   the reference bit for bit, including language changes and reset.
4. Build-time failure links and minimum-ranked substring outputs make Punto
   matching incremental. Separate rooted paths preserve beginning/exact rules;
   exact matches expire after another character. Original-case and lowercase
   streams keep native rule precedence. Bounded snapshots recover all states
   after Backspace, edits and skipped samples. Standalone whole-word queries
   retain the indexed trie, which benchmarks faster for that workload.
5. The adapter caches whether completed visible context is waiting for an
   anchor. Boundaries, Backspace, clearing, layout changes, policy changes and
   changed mappings invalidate or bypass it. Maps that introduce a space inside
   the current word use the uncached path. Actual correction still verifies
   the visible suffix.

`PartialWordState::evaluate_physical` accepts a borrowed physical word; the
owned-sample and stateless APIs remain available. Non-ASCII physical input uses
the general Unicode evaluator. Current mapping, layout and policy guards remain
active on every evaluation; cached rules never override exceptions or Keep.

## Boundary scoring and long-session cache follow-up

Completed-word scoring now keeps four bounded states (English/Ukrainian,
word/context), reusing normalized tokens and exact integer prefix sums. Changed
or reordered tokens are rescored; unchanged tokens keep their contributions.
Inputs beyond 1,024 bytes or 128 tokens use the stateless path. Other model
artifacts bypass the production caches. Context bigram lookup reuses 16 word
IDs, including misses, and uses stack arrays for its maximum three words.

The token cache no longer clears 65,536 entries at once. It uses 8-way buckets
with clock eviction, allocating pages/buckets lazily. A full bucket replaces
one entry after at most eight reference-bit checks; exact string equality
protects hash collisions. Tokens over 256 bytes bypass caching. The maximum
is still 65,536 entries, but association conflicts can evict earlier: the
67,584-token replay retains about 57,000 entries. Eviction changes performance,
not scoring. No model, dictionary or rule asset changes.

measures the macOS Space/Enter snapshot and evaluator, excluding preceding
letter ingestion and actual editor interaction. Modes `cold-boundary`, `score`,

capacity pressure. Cold-boundary resets caches before each sentence; it does
not measure application launch or cold OS pages. Allocation accounting uses a

## Compact cold caches and borrowed boundary text

The sparse token cache now ranks occupied page slots with two 64-bit bitmaps
and stores only their buckets. Pages grow geometrically to at most 128 buckets;
buckets grow through 1/2/4/8 entries. Clock reference bits, the 65,536-entry
limit, the 256-byte cache-key limit and exact-key comparisons are unchanged.
Growth can move one bounded page (at most 128 bucket records), never the whole
cache. No unsafe storage or pointer dereferences were introduced.

Word/token normalization borrows already canonical lowercase text. Filtering,
apostrophe conversion, contextual Greek sigma and Unicode lowercase expansion
retain their original ordering. Token iteration no longer collects a temporary
Vec. N-grams use a 66-character stack buffer for up to 64 lowercase characters,
with a heap fallback for longer inputs; n-gram order and weights are identical.

Completed-context tokens hold byte ranges into the state's retained source
text instead of separate raw/normalized strings. The old text remains intact
until all comparisons and prefix sums finish; then the ranges refer to the new
text. Exact repeated contexts return before tokenization. The four bounded
word/context states and alternate-model bypass remain unchanged.

## UTF-8 prefix trimming and one visible-context rendering

Source-language prefix trimming now walks borrowed UTF-8 slices instead of
building two `Vec<char>` values and temporary word strings. Corresponding
target positions are counted in Unicode scalars, so different byte widths and
custom mappings of spaces preserve the old behavior. Unequal scalar counts
still return the original correction. Scorer calls retain their original order.
Small correction buffers are shortened in place; a buffer larger than both
1,024 bytes and twice the remaining tail is replaced with a compact allocation.
This avoids retaining huge public inputs, while ordinary shortened results may
keep their original buffer capacity.

Desktop evaluation renders the actual visible layout runs once and passes the
borrowed result through ordinary, Caps Lock, Enter and terminal checks. This is
local to one decision and adds no persistent cache. Caps Lock's intended-text
retry still uses the original visible runs, preserving the text to replace.

The two changes were implemented and checked in sequence. Final measurements
use six alternating AB/BA pairs on Apple M5 with identical release harnesses,

## Streaming visible layout runs

A single English layout run now borrows its snapshot's physical text through
`Cow<str>`. Empty context also borrows an empty string. Other contexts reserve
one output buffer from their physical byte lengths, then append converted
Ukrainian runs directly. The new `layout::append_converted` API preserves the
existing conversion rules: first custom pair wins, absent pairs leave the
character intact, an empty custom mapping is distinct from the built-in map,
and Smart direction examines only the appended input. Existing conversion
APIs are unchanged. Rendering adds no persistent cache or tracker fields.

Six alternating AB/BA pairs use the same release harness, independent clean
builds and all raw samples. A new `visible` workload isolates rendering from

## Controlled follow-up of the Enter tail

The prior cold-Enter increase of approximately 7% was investigated with the
exact pre-streaming and current host sources compiled into one executable,
sharing the same core implementation. Each sentence is replayed by both hosts
in alternating AB/BA order. Cold workloads reset token/context caches before
each sentence, matching the original replay's definition of cold. A separate
current/current comparison controls for order and measurement variation. Both
the initial side and the order of comparison/control workloads alternate
between processes.

Two fixed series each contain six independent processes: one uses the ordinary
system allocator, the other retains the original benchmark's counting allocator
with counters disabled during timing. Each series contributes 36,000 boundary
events per side per workload, including 36,000 cold Enter events. Host typing
and context each use 40 interleaved full replay batches per side per process;
the batches contain 8,465 and 14,965 queries respectively. No builds or tests
run concurrently. All samples, including large shared outliers, are retained.

| Comparison | System allocator, before → after | Original allocator instrumentation, before → after |
| --- | ---: | ---: |
| Cold Enter p50 | 1.896 → 1.875 µs | 1.917 → 1.917 µs |
| Cold Enter p95 | 5.771 → 5.771 µs | 5.875 → 5.917 µs |
| Cold Enter p99 | 6.146 → 6.125 µs | 6.209 → 6.271 µs |
| Warm Enter p99 | 3.834 → 3.834 µs | 4.021 → 4.021 µs |
| Host typing median | 376.0 → 373.5 ns/query | 389.0 → 387.0 ns/query |
| Host context median | 260.5 → 256.0 ns/query | 276.0 → 272.5 ns/query |

The table uses medians of per-process quantiles. The median *paired* cold Enter
p99 difference is 0 ns with the system allocator and +20.5 ns with allocator
instrumentation. Current/current cold Enter p99 is 6.000 → 6.021 µs and
6.250 → 6.250 µs respectively. Some individual processes still have large
outliers in both implementations; those runs are included, not filtered out.

The prior 7% increase does not reproduce in these controlled comparisons.
Observed median-of-quantile differences are approximately −0.3% and +1.0%,
depending on instrumentation, so no broad speedup or guaranteed zero regression
is claimed. The earlier separate-process observations remain in the report as
evidence of measurement variability. They are no longer treated as an established
cost of the renderer change. The runtime is retained without another edit or
reinstallation; its allocation savings from the previous stage remain valid.

Every paired decision checksum matches, and exact source/asset hashes confirm
that the production implementation and all 13 language/rule assets were not
changed during this audit. The installed binary hashes, running process, CLI
conversion cases and configuration were also checked. The previous full
422-test validation still applies; this audit adds benchmark comparisons and
does not rerun unchanged unit tests.

The archived host sources, probe source, executable hashes, per-event traces and
reports are in `.stos/engine-tail-audit/` and its `counted/` subdirectory.
`report.json` links both series and records the interpretation. Future small
latency claims should use paired same-process comparisons and a current/current
control before being attributed to an engine change. These measurements do not
include editor response time or desktop input.

## Prepared custom keyboard mappings

`convert_with_mapping` and the custom-map branch of `append_converted` now
reuse one prepared mapping per calling thread. Each direction has a direct
128-character ASCII table and sorted non-ASCII pairs. Stable sorting and
deduplication preserve the original first matching pair in both directions,
including duplicate sources, duplicate destinations and identity pairs.
Unmapped characters and Smart direction keep their previous behavior.

The cache compares the complete input slice, so edits at the same address are
noticed. It retains only the last eligible mapping, with 8–256 input pairs.
Smaller and larger mappings use the original linear path; empty input does not
prepare an index. A hit performs an O(m) content comparison followed by direct
ASCII lookup or O(log m) non-ASCII lookup per character. There is no map hashing
or per-character linear scan on an indexed conversion. Built-in conversion
without a custom mapping and the existing mid-word direct table are unchanged.

On Apple M5, six adjacent before/after pairs use independently built release
binaries with the same harness. Each conversion workload contributes 36,000
samples per version. Median of per-process quantiles:

| Workload | p50 before → after | p99 before → after |
| --- | ---: | ---: |
| Ten-character physical word | 84 → 83 ns | 167 → 125 ns |
| Longer physical context | 417 → 167 ns | 563 → 313 ns |
| Ukrainian context → English | 396 → 209 ns | 605 → 500 ns |
| Visible mixed runs with supplied layout pairs | 209 → 125 ns | 292 → 230 ns |
| First conversion after index reset | 84 → 625 ns | 209 → 4,480 ns |
| Mapping changed on every conversion | 41 → 646 ns | 42 → 1,271 ns |

Preparation is an explicit tradeoff. The standard 75-pair mapping retains
2,720 requested heap bytes per active thread, including the owned source,
both indexes and their vectors. Building it takes eight allocation calls;
steady-state conversion adds no index allocation. Replacing this map temporarily
reaches 5,440 bytes while both old and new allocations exist. Tiny/oversized-map
probes retain no index. This memory is measured separately: full boundary and
per-key allocation replays start after warmup and therefore exclude an already
prepared index. Requested heap counts are not RSS.

Very short conversions do not show the long-context benefit: a one-byte `q`
probe moves from approximately 21 to 42 ns and a two-byte word stays near
42 ns. These approach the clock's roughly 42 ns resolution; no precise
single-character speed ratio is claimed. Frequently changing a public map
also pays rebuilding costs. The installed layout is stable, allowing the
prepared mapping to be reused across boundary decisions and rendering.

The complete per-key process CPU median is effectively unchanged at
4.145 → 4.150 seconds. Space/Enter full-replay allocation calls and core/host
state sizes remain unchanged. Separate-process warm boundary p99 is
4.208 → 4.209 µs for Space and 3.959 → 4.125 µs for Enter; those values alone
are not used to claim whole-engine acceleration.

Six additional same-process invocations use identical host implementations and
one shared core, selecting the preserved linear path or the prepared path
before each replay. Benchmark-only selection and cache inspection are excluded
from the production build. AB/BA sentence ordering and current/current controls
retain all samples. Each boundary workload has 36,000 events per side; per-key
timings use 40 full batches per side per process.

| Space, warm | 0.959 → 0.979 µs | 3.667 → 3.542 µs | 4.292 → 4.209 µs |
| Enter, warm | 1.438 → 1.459 µs | 3.625 → 3.521 µs | 4.479 → 4.230 µs |

Host typing medians are 386.5 → 377.5 ns/query; host context is

All before/after and paired decision checksums match, including 54,486 full

## Portable engine regression contract

The optimization sequence is now covered by one reproducible offline command:

```sh
python3 tools/run_engine_contract.py
```

It builds only the core's `engine_contract` release example with the existing
`engine-bench` feature and locked, cached dependencies. It needs neither the
downloaded `.cache/` corpus nor the local `.stos/` measurement archives, desktop
permissions or OS layout APIs. The committed 191-case boundary fixture supplies
6,076 incremental/reference comparisons, including append and Backspace, and
1,146 linear/prepared boundary-decision comparisons. Mismatch budgets are zero;
minimum comparison counts prevent an empty replay from passing.

Budgets live in `crates/upyr-core/fixtures/engine-budgets-v1.tsv` and are reviewed
as explicit constraints, not regenerated from each measurement:

| Check | Limit |
| --- | ---: |
| Allocations in warmed native-word prefix replay | 0 |
| Corrections to the native-word warmup fixture | 0 |
| Allocations in warmed mapped append into a reserved buffer | 0 |
| Standard prepared-map requested heap | 3,072 bytes |
| Maximum eligible map and retained replacement heap | 8,192 bytes |
| Peak requested heap while replacing the maximum map | 16,384 bytes |
| Index heap after only tiny/oversized maps | 0 |
| Token entries after 131,072 distinct tokens | 50,000–65,536 |
| Automatic decreases in token-cache occupancy during insertion | 0 |
| Token-cache retained / peak requested heap | 4.5 / 4.6 MB |
| Allocations for warmed hits on the last inserted token | 0 |

The occupancy check detects a return to clearing the entire token cache under
pressure. A negative-control run in an isolated copy injected one full cache
reset during replay: this check failed while the other 17 checks passed.
Random bucket distribution can change the final entry count and a
small amount of heap, so those checks use bounds. Mapping storage includes
the owned source and both indexes. Replacement measurement includes overlap
between old/new indexes. Warmed append uses a preallocated output buffer;
its zero-allocation budget does not apply to public conversion APIs that must
return an owned string. All heap counters measure requested bytes, not RSS.

The runner independently validates all 18 expected check/relation pairs and
their checked-in limits. Missing, duplicate, malformed or inconsistent rows
fail the run even if the child exits successfully. Cargo failures and timeouts
retain their logs and partial checks. The JSON report records the source/asset/
fixture fingerprint, platform and failure details; the default files are
`target/engine-contract-report.json` and `target/engine-contract-report.log`.

CI is configured to run the contract in the existing macOS/Windows/Linux test
matrix and upload both artifacts for 14 days on success or failure. The native
example and budget fixture are included in the core source package. The normal
workspace tests and WASM contract remain separate checks.

There is deliberately no nanosecond gate on shared CI machines. Future latency
claims still require paired measurements with controls and retained samples.
This addition changes validation and CI, not the installed engine's decisions
or execution path.
